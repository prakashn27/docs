## Architecture Overview

Support Unicorn follows a layered architecture with clear separation of concerns.

## Architecture Layers

### 1. MVC Pattern (Rails Standard)

- **Models** (`app/models/`): Domain models with business logic, validations, scopes
- **Views** (`app/views/`): ERB templates, Jbuilder for JSON APIs
- **Controllers** (`app/controllers/`): Handle HTTP requests, delegate business logic to services

### 2. Service Layer Pattern

Business logic lives in `app/services/` classes. Controllers are thin and delegate to services.

**Service Types**:
- **API Clients**: External API integrations using HTTParty (e.g., `StripeService`, `TwilioService`, `ZendeskService`)
- **Business Logic Services**: Core application logic (e.g., `BillingService`, `EscalationService`, `AiChatService`)
- **Integration Services**: Platform-specific logic (e.g., `SlackService`, `ZendeskService`)

### 3. Background Jobs (SolidQueue)

Async processing in `app/jobs/`:
- File processing: `file_processing` queue for resource-intensive work
- Credit tracking: Async credit deduction after AI messages
- Webhook processing: Background handling where appropriate

### 4. Real-time Communication (ActionCable/SolidCable)

- WebSocket connections for live chat
- Channel subscriptions: `session_{session_id}` for widget conversations
- Broadcast messages for real-time updates

### 5. RAG Architecture (Retrieval-Augmented Generation)

- **Turbopuffer**: Vector database for semantic search
- **OpenAI**: Embedding generation and chat completions
- **Unstructured.io**: Document parsing and chunking
- **S3/Active Storage**: File storage for knowledge base documents

## Directory Structure

```
app/
  ├── controllers/        # HTTP request handlers (thin, delegate to services)
  │   ├── agents/         # Nested agent-related controllers
  │   └── api/            # API endpoints
  ├── models/             # ActiveRecord models with business logic
  ├── services/           # Business logic and external API clients
  ├── jobs/               # Background jobs (SolidQueue)
  ├── channels/           # ActionCable channels
  ├── views/              # ERB templates and Jbuilder JSON
  ├── javascript/         # Frontend code
  │   ├── controllers/   # Stimulus controllers
  │   ├── entrypoints/    # SDK and widget entry points
  │   └── sdk/            # Widget SDK utilities
  └── helpers/            # View helpers

config/
  ├── routes.rb           # Route definitions
  ├── environments/       # Environment-specific config
  └── initializers/       # Initialization code

db/
  ├── migrate/            # Database migrations
  ├── schema.rb           # Current database schema
  └── seeds.rb            # Seed data
```

## Data Flow

### Widget Message Flow

```
Customer → Widget SDK → ActionCable → LiveChatService
                                              ↓
                                    AiChatService
                                              ↓
                                    Turbopuffer (vector search)
                                              ↓
                                    OpenAI (generate response)
                                              ↓
                                    ActionCable → Widget → Customer
```

### File Processing Flow

```
File Upload → Active Storage (S3)
                    ↓
            ProcessFileJob (enqueued)
                    ↓
            UnstructuredService (parse)
                    ↓
            OpenAI (embed)
                    ↓
            TurbopufferService (store vectors)
```

## Technology Stack

### Backend

- **Ruby**: 3.4.4
- **Rails**: 8.0.2
- **Database**: PostgreSQL (primary), SQLite (for SolidCache, SolidQueue, SolidCable)
- **Job Processing**: SolidQueue
- **Cache**: SolidCache
- **WebSockets**: SolidCable (ActionCable)

### Frontend

- **Hotwire**: Turbo + Stimulus
- **Asset Pipeline**: Propshaft
- **JavaScript**: Importmap (ES modules)
- **Widget SDK**: Vanilla JavaScript (no framework dependencies)

### External Services

- **OpenAI**: Embeddings and chat completions
- **Turbopuffer**: Vector search
- **Unstructured.io**: Document processing
- **AWS S3**: File storage (via Active Storage)
- **Stripe**: Payments and subscriptions
- **Twilio**: SMS/WhatsApp
- **Slack**: Team communication
- **Zendesk**: Ticket management

## Design Patterns

### Service Object Pattern

Business logic is encapsulated in service objects:

```ruby
class AiChatService
  def initialize(conversation)
    @conversation = conversation
  end

  def process_message(message)
    # Business logic here
  end
end
```

### Repository Pattern

Data access is abstracted through models:

```ruby
class Agent
  has_many :agent_data_sources
  has_many :data_sources, through: :agent_data_sources
end
```

### Background Job Pattern

Long-running tasks are processed asynchronously:

```ruby
ProcessFileJob.perform_later(file_data_source.id)
```
