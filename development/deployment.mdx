## Deployment Options

### Fly.io (Recommended)

Support Unicorn is configured for Fly.io deployment.

#### Initial Setup

```bash
# Install Fly CLI
curl -L https://fly.io/install.sh | sh

# Login
fly auth login

# Launch app
fly launch
```

#### Configure Secrets

```bash
# Set environment variables
fly secrets set DATABASE_URL=postgresql://...
fly secrets set OPENAI_API_KEY=...
fly secrets set TURBOPUFFER_API_KEY=...
fly secrets set UNSTRUCTURED_API_KEY=...
fly secrets set STRIPE_SECRET_KEY=...
fly secrets set RAILS_MASTER_KEY=...
```

#### Deploy

```bash
# Deploy to production
fly deploy

# Deploy automatically runs migrations including cable
```

#### Database

The application uses [Neon DB](https://neon.tech) for PostgreSQL.

### Other Platforms

Support Unicorn can be deployed to:

- **Heroku**: Standard Rails deployment
- **Render**: Rails service with PostgreSQL
- **AWS**: EC2, ECS, or Elastic Beanstalk
- **DigitalOcean**: App Platform or Droplets

## Database Migrations

Migrations run automatically during deployment on Fly.io:

```bash
# Manual migration (if needed)
fly ssh console -C "bin/rails db:migrate"
```

### Cable Migrations

Cable migrations are included in the deployment process:

```bash
# Manual cable migration (if needed)
fly ssh console -C "bin/rails db:migrate:cable"
```

## Background Jobs

### SolidQueue Configuration

SolidQueue runs as part of the web process by default. For production, consider:

1. **Separate worker process**: Run workers on dedicated machines
2. **Scale workers**: Adjust worker count based on load
3. **Queue configuration**: Tune queue settings in `config/queue.yml`

### Fly.io Multi-Machine Setup

```toml
# fly.toml
[processes]
  web = "bin/rails server"
  worker = "bin/rails solid_queue:start"

[[vm]]
  processes = ["web"]
  size = "shared-cpu-1x"
  count = 2

[[vm]]
  processes = ["worker"]
  size = "shared-cpu-2x"
  count = 2
```

## SSL/TLS

Fly.io provides automatic SSL certificates. For other platforms:

- **Let's Encrypt**: Free SSL certificates
- **Cloudflare**: SSL proxy
- **Platform SSL**: Use platform-provided SSL

## Performance Optimization

### Asset Compilation

Assets are compiled during deployment. For CDN:

1. Configure CDN for static assets
2. Set `ASSET_HOST` environment variable
3. Update asset URLs in views

### Database Connection Pooling

Configure connection pooling in `config/database.yml`:

```yaml
production:
  pool: <%= ENV.fetch("RAILS_MAX_THREADS") { 5 } %>
```

### Caching

Configure caching in `config/environments/production.rb`:

```ruby
config.cache_store = :solid_cache_store
```

## Security

### Secrets Management

- **Never commit secrets** to version control
- Use environment variables or secrets management
- Rotate secrets regularly

### CSRF Protection

CSRF protection is enabled by default. Webhook endpoints have CSRF disabled (necessary for external services).

### CORS

CORS is configured for widget endpoints. Adjust in `config/application.rb` if needed.

## Troubleshooting

### Deployment Fails

- Check build logs
- Verify all environment variables are set
- Ensure database is accessible
- Check migration status

### Jobs Not Processing

- Verify SolidQueue is running
- Check worker configuration
- Review job dashboard
- Check logs for errors

### WebSocket Not Working

- Verify ActionCable is mounted at `/cable`
- Check SSL certificate is valid
- Review WebSocket connection logs
