## Overview

Escalations allow your AI agent to seamlessly hand off conversations to human agents when needed. They can be triggered manually by customers or automatically based on conditions you define.

## Supported Platforms

Support Unicorn can escalate conversations to multiple platforms:

- **Slack**: Create notifications in Slack channels
- **Zendesk**: Automatically create support tickets
- **Jira**: Create issues in Jira projects
- **Microsoft Teams**: Send notifications to Teams channels

## Creating an Escalation Path

### Via Web Interface

1. Navigate to **Agents** → **Your Agent** → **Escalations**
2. Click **"Create Escalation Path"**
3. Fill in the required information:
   - **Name**: A descriptive name for this escalation path
   - **Platform**: Choose your escalation platform (Slack, Zendesk, Jira, or Teams)
   - **Platform Integration**: Select the connected integration account
4. Configure platform-specific settings (see below)
5. Set up triggers (optional)
6. Click **"Save"**

## Platform-Specific Configuration

### Slack

When escalating to Slack, configure:

- **Escalation Channel**: The Slack channel where notifications will be sent
- **Notification Template** (optional): Custom message format
- **Mention Users** (optional): Automatically mention specific users
- **Thread Replies**: Whether responses should be in threads

**Example Use Case:** Escalate urgent customer issues to `#customer-support` channel with mentions to on-call team members.

### Zendesk

When escalating to Zendesk, configure:

- **Default Priority**: normal, low, high, or urgent
- **Default Type**: question, incident, problem, or task
- **Tags** (optional): Automatically apply tags to tickets
- **Group ID** (optional): Assign to a specific support group
- **Subject Template** (optional): Custom ticket subject format

**Example Use Case:** Create high-priority tickets for billing issues, automatically tagged with "ai-escalation" and assigned to the billing team.

### Jira

When escalating to Jira, configure:

- **Project Key**: The Jira project where issues will be created
- **Issue Type**: Bug, Task, Story, etc.
- **Priority** (optional): Set default priority
- **Assignee** (optional): Auto-assign to a specific user
- **Labels** (optional): Add labels to issues
- **Components** (optional): Associate with project components

**Example Use Case:** Create bug reports in your support project when customers report technical issues.

### Microsoft Teams

When escalating to Teams, configure:

- **Team ID**: The Teams team to notify
- **Channel ID**: The specific channel for notifications
- **Notification Template** (optional): Custom message format
- **Mention Users** (optional): Automatically mention team members
- **Adaptive Card Template** (optional): Use custom card design

**Example Use Case:** Notify your support team in Microsoft Teams when AI confidence is low or customer is unsatisfied.

## Escalation Triggers

You can configure when escalations should be triggered automatically:

### Manual Only

The AI agent will never auto-escalate. Escalation only happens when:
- Customer explicitly requests human help
- AI agent determines it cannot help (low confidence)

### Message Count

Automatically escalate after a specific number of customer messages.

**Configuration:**
- Set the message threshold (e.g., 5 messages)

**Use Case:** If a conversation goes back and forth too many times, it may indicate the AI isn't solving the problem.

### Keywords

Automatically escalate when specific keywords are detected in customer messages.

**Configuration:**
- Enter keywords separated by commas (e.g., "refund, cancel, manager, complaint")

**Use Case:** Sensitive topics like refunds or cancellations that require human judgment.

### Sentiment (Coming Soon)

Automatically escalate when negative sentiment is detected.

## How Escalations Work

When an escalation is triggered:

1. **Notification Created**: A ticket, issue, or message is created in your chosen platform
2. **AI Disabled**: The AI agent stops responding to that conversation
3. **Human Notified**: Your support team receives notification via the platform
4. **Context Preserved**: Full conversation history is included in the escalation
5. **Conversation Continues**: Human agents can respond through the original channel

## Using Escalations in Procedures

You can reference escalation paths in your AI agent procedures using the `{{escalate}}` syntax:

```markdown
If the customer needs more help:
{{escalate:escal_path_support}}
I've connected you with our support team who will assist you shortly.
```

## Testing Escalations

Before going live, test your escalation paths:

1. Go to **Agents** → **Your Agent** → **Escalations**
2. Find the escalation path you want to test
3. Click **"Test Connection"**
4. Verify:
   - Test notification appears in the platform
   - Required fields are populated correctly
   - Team members receive notifications

## Managing Escalation Paths

### Activate/Deactivate

You can temporarily disable an escalation path:

1. Navigate to **Agents** → **Your Agent** → **Escalations**
2. Find the escalation path
3. Toggle the **"Active"** switch

**Note:** Inactive escalation paths won't trigger, even if conditions are met.

### Edit Settings

1. Navigate to **Agents** → **Your Agent** → **Escalations**
2. Click the escalation path you want to edit
3. Update configuration
4. Click **"Save Changes"**

### Priority Order

If you have multiple escalation paths, you can set their priority:

1. Navigate to **Agents** → **Your Agent** → **Escalations**
2. Drag and drop to reorder
3. Higher priority paths are evaluated first

## Best Practices

1. **Clear Criteria**: Define specific conditions for when to escalate
2. **Multiple Paths**: Set up different paths for different scenarios (e.g., billing vs technical issues)
3. **Test Regularly**: Ensure escalation paths work and notifications reach the right people
4. **Monitor Rates**: Track how often escalations happen to improve your AI agent
5. **Quick Response**: Have a team process for responding to escalated conversations promptly
6. **Provide Context**: Include relevant conversation context in escalation templates

## Common Escalation Scenarios

### Scenario 1: Billing Issues
- **Platform**: Zendesk
- **Trigger**: Keywords ("refund", "charge", "billing")
- **Priority**: High
- **Auto-assign**: Billing team

### Scenario 2: Technical Problems
- **Platform**: Jira
- **Trigger**: Keywords ("error", "broken", "not working")
- **Issue Type**: Bug
- **Auto-assign**: Engineering team

### Scenario 3: Extended Conversations
- **Platform**: Slack
- **Trigger**: Message count (>5 messages)
- **Channel**: #support-overflow
- **Mention**: On-call support agent

### Scenario 4: VIP Customers
- **Platform**: Microsoft Teams
- **Trigger**: Manual (detected by AI based on account status)
- **Priority**: Urgent
- **Mention**: Account managers

## Troubleshooting

### Escalation Not Triggering

- Verify the escalation path is **active**
- Check that triggers are configured correctly
- Ensure the platform integration is connected
- Review conversation to confirm trigger conditions were met

### Platform Not Receiving Notifications

- Test the connection using **"Test Connection"** button
- Verify platform integration credentials are valid
- Check platform-specific settings (channel ID, project key, etc.)
- Review platform integration logs for errors
- Ensure platform service is not down

### Missing Context in Escalations

- Check that notification templates include conversation variables
- Verify webhook is configured correctly for the platform
- Review escalation service logs

### Duplicate Escalations

- Check that you don't have multiple active escalation paths with overlapping triggers
- Adjust trigger conditions to be more specific
- Set priority order to control which path triggers first
